# 数据与伦理

## 这个仓库里没有任何数据

没有照片、没有清洗后的数据集、没有导出的特征、没有训练好的权重。
`train/` 里是脚本，脚本要么用仓库相对路径，要么让你自己指定数据目录。

这不是洁癖，是三个具体原因。

## 一、我们用的那批数据不能再用

项目早期用过一份公开的"面部卒中"数据集（Kaggle 上的一个上传，约 3749 张，
标注为卒中 1249 / 非卒中 2500）。后来查明：

- 该数据集在 2026 年 7 月被 Kaggle 以**版权侵权**为由下架，内容是从论文和公开报道里抓的图，
  其中包含一名未成年人；
- 对应的期刊论文在 2026 年 6 月被撤稿。

也就是说，这批图我们既没有分发的权利，也没有把它当作研究材料的正当理由。
现在它只在本机留作工程测试用，不进仓库、不进安装包、不再对外。

## 二、就算它有版权，标签也是坏的

这是更关键的一点。我们对这批数据做了一轮审计，结论很不好看：

| 检验 | 结果 | 说明 |
| --- | --- | --- |
| 只用颜色特征，随机划分 | AUC 0.9998 | 高得不正常 |
| 只用颜色特征，按来源聚类划分 | AUC 0.9987 | 依然高，说明不是划分的问题 |
| 只取"参考区"的颜色（不含中央区） | AUC 0.7301 | 参考区自己就能分，说明分的是来源不是病理 |
| 只用图像的饱和度 | AUC 0.738 | 连一个退化特征都能分 |
| 只用清晰度 | AUC 0.730 | 同上 |
| 只用几何（对称度） | AUC 0.78–0.82 | 检测率 99.5% vs 99.0%，两组几乎一样 |
| 两组图像的常见尺寸 | 215×300 / 300×278 与 225×225 / 275×183 | 采集来源不同，尺寸分布也不同 |

把这些放在一起只有一种解释：**模型学到的是"这张图是从哪个来源抓来的"，
而不是"这个人有没有病"。** 标签和采集来源完全重叠，任何基于随机划分的性能数字都是无效的。

同类的证据还有一条：库内最近邻检索的准确率 99.2%，其中 98.3% 的最近邻来自同一采集来源。
以及，把画面背景当参考区做校正之后，跨光源的残留（4.83 / 7.36 / 3.86 ΔE）
反而**大于**未校正时的原始差异（1.14 / 2.97 / 3.57 ΔE）——用背景做参考不仅无效，还会放大差异。

顺带说明一个被混淆的概念：那批数据里"stroke" 文件夹混着贝尔面瘫（Bell's palsy）的图。
面瘫是周围性面神经麻痹，和卒中是两回事。所以即便数据来源干净，标签也只能叫"明显面部不对称"，
不能叫"卒中"。仓库里所有文案都不再使用卒中相关表述，原因就在这里。

## 三、人脸数据本身的规矩

- 本项目不收集、不上传、不记录任何人脸图像。处理全在设备内完成，原始帧用完即丢。
- 测量记录只存数值，不存图。
- 如果将来要接云端汇总，前提是先做完个人信息保护影响评估、签数据协议，
  并且只上传去标识化的特征与元数据 —— 这三件事都不在代码里，属于运营方责任。

## 对使用者的要求

1. **自己准备数据，自己确认许可。** 公开人脸数据集大多禁止商用
   （例如 300W 明确写了"不得用于训练商业算法"；CelebA 禁止将图像或任何派生数据用于商业用途）。
   动手前请读一遍你要用的那份的条款。
2. **不要把别人的脸放进仓库。** 一个 issue 里附一张图就够了，不需要数据集。
3. **不要把内部数据产出当成 benchmark。** 如果你的数据也是从单一来源抓的，
   那你测出来的大概率也是"来源可分性"，不是生理信号。

## 我们做错过的两件事，写在这里当反面教材

- 早期版本在结果页展示过"模型指标"，还带样本量和 AUC。这既违反了自己定的文案红线，
  也把无效的数字当成了证据。已在 v1.4.1 全部移除。
- 早期版本用百分制分数呈现对称度，但没有说明这个分数相对什么。
  一个没有参照的分数会被当成"健康状况打分"。现在分数必须同时给出参考分布和误差范围。
